# Routing containment fixtures

`harness.mjs` builds disposable Git projects with ordinary current-head Tester
and Adversary reports, routing enabled, and Evidence Judge absent. It drives the
real coordinator, preparation, accounting, pinned Jev protocol, deterministic
policy, human presentation and separately authorized follow-up. Its `fetch`
double intercepts exact serialized bytes before any socket is opened. Credentials
are synthetic. No live provider, account, endpoint or credential is required.

`routing-boundary.test.mjs` compares all non-routing checkpoint bytes, ticket
contents, head, claim and refs around assessments. Table-driven attacks cover
outbound and inbound snapshots, protocol/transport substitutions, corrupt caches,
preflight/consent refusals, stale responses, budget contention and recovery,
and assessment-to-human-follow-up-to-retired-report replay. Child processes exit
before/after reservations and while holding checkpoint locks. The existing focused
routing suites retain the exhaustive schema/policy and low-level transport tests;
the full orchestration suite runs both layers, including loopback redirect tests.

These tests establish bounded projection and restricted-prose screening, not
complete DLP. Ordinary prose can still contain unrecognized sensitive material.
Cache integrity detects stale/corrupt/altered persistence records; it does not
protect against an actor who can rewrite both content and integrity metadata.
