    Components

    At the edge

    What a client touches. Intended, not built.

    A clientactor

    Would send a token on every request and expect the same answer from any region.

    API gatewayinterface

    Would terminate TLS, apply rate limits, and route. It would hold no session state.

    Token serviceservice

    Would verify tokens and nothing else. Deliberately not the place where permissions live.

    The read path

    Would answer from cache wherever it can, and never wait on the write path.

    Read serviceservice

    Would serve every query, and would be the only thing allowed to answer from the cache.

    Read cachestore

    Would hold projections, never authoritative state. Safe to lose entirely.

    Projection storestore

    Would be rebuildable from the event log, which is what makes a cold start survivable.

    Stale or missing?decision

    Would decide whether to answer from the cache or fall through to projections.

    The write path

    Would own every mutation, and publish what happened rather than call whoever cares.

    Write serviceservice

    Would own every mutation. The one writer of authoritative state.

    Authoritative storestore

    Would be the single source of truth, and would never be read by the read path directly.

    change-eventsqueue

    Would carry what happened, never what should happen next.

    Not in a boundary

    Projectorjob

    Would consume events and maintain projections. Idempotent, so a replay is safe.

    Cache invalidatorjob

    Would consume the same events and evict rather than write. Two consumers, one log.

    Answeredterminal

    Would be reached from either branch, which is the property worth designing for.

    Paths

    A query that hits

    Four steps and nothing authoritative is read, which is the whole reason the read path exists.

    Walks
    1. A client calls API gateway — a query
    2. API gateway calls Read service — routes the query
    3. Read service becomes Stale or missing? — cache first
    4. Stale or missing? reads Read cache — on a hit

    A query that misses

    The same first three steps, then a fall-through to projections rather than to the authoritative store.

    Walks
    1. A client calls API gateway — a query
    2. API gateway calls Read service — routes the query
    3. Read service becomes Stale or missing? — cache first
    4. Stale or missing? reads Projection store — on a miss

    A mutation, and its wake

    The write path would publish once and be finished; two independent consumers would then do their own work.

    Walks
    1. A client calls Write service — a mutation
    2. Write service writes Authoritative store — commits

    Views

    One log, two consumers

    The projector maintains and the invalidator evicts. Neither would know about the other, and that independence is the design.
