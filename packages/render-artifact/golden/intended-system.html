Components

At the edge

What a customer would touch. Intended, not built.

Customeractor

Places an order and expects one confirmation, not three.

Storefrontinterface

Would accept the order and hand it on without holding it.

Order handling

Order serviceservice

Would own the order's lifecycle and nothing else.

Order ledgerstore

Would be the only writer of order state.

order-eventsqueue

Would carry what happened, never what should happen next.

Not in a boundary

Paymentsexternal

A third party. Would be called once, idempotently.

Fulfilmentjob

Would consume events rather than being called.

Retrydecision

Would decide whether a failed charge is worth another attempt.

Paths

The intended happy path

Three steps, and the order is durable in the ledger before anybody is charged.

Walks
  1. Customer calls Storefront — places an order
  2. Storefront calls Order service — submits
  3. Order service writes Order ledger — order state

Charging, and failing

The walk returns to the payment provider it just left, which is a cycle and a fact about retries rather than a modelling slip.

Walks
  1. Order service calls Payments — charge
  2. Payments triggers Retry — on failure
  3. Retry calls Payments — retries once
