How create-pathfinder installs the kit

One npx invocation, from the registry to a destination project's working tree

Components

Entry

The executable npm exposes, and the one function it hands control to.

The whole install, in one async function: locate the kit, ask, plan, apply, report.

Paths

A first install

Six steps from one typed command to a changed working tree, and the human is asked before any of it is written.

Walks
  1. The developer triggers The npm registry — npx
  2. The npm registry triggers create-pathfinder — runs the bin
  3. create-pathfinder calls run() — run(argv)
  4. run() calls planInstall() — plans the copy
  5. planInstall() becomes applyPlan() — once accepted
  6. applyPlan() writes The project — the kit
Evidence
  • packages/create-pathfinder/src/cli.mjslines 81–90

The off switch

Two callers ask the same question — the installer at install time and the staging script at pack time — which is why a file kept out of one is kept out of both.

Walks
  1. run() calls planInstall() — plans the copy
  2. planInstall() calls neverShips() — excludes
Evidence
  • packages/create-pathfinder/src/kit.mjslines 114–130

Packed, then run

Walks
  1. stage-kit.mjs publishes to The npm registry — package contents
  2. The npm registry triggers create-pathfinder — runs the bin
  3. create-pathfinder calls run() — run(argv)
