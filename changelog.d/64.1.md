- A project can record where orchestrated workers execute with
  `<!-- pathfinder:execution-environment local|sandbox -->` in
  `context/execution-mode.md`; no line is `local`, and any other value is
  invalid. `npx create-pathfinder --environment <local|sandbox>` writes the
  line and keeps an existing one across re-runs and mode changes. A sandbox
  also needs `<!-- pathfinder:sandbox-permission-mode bypassPermissions|acceptEdits -->`,
  chosen explicitly with no default, and may declare a Claude subscription
  sign-in with `<!-- pathfinder:sandbox-agent-auth subscription -->`; the
  installer keeps both lines.
- `orchestrate environment [--harness <h>] [--json]` reports, read-only,
  whether the selected environment is ready: environment, harness,
  permission mode, platform, `sbx` runtime and version, and each check's
  status (`ready`, `missing`, `unsupported`, `not-ready`,
  `authentication-required`) with its remediation; a `declared` subscription
  and host access every sandbox inherits (SSH agent forwarding, the host
  browser, global secrets by service name, the network policy) are reported
  as warnings and never changed. It exits 0 only when nothing blocks.
  `local` probes nothing. `sandbox` is supported only for `claude-code` on
  macOS 14+ on Apple silicon, probes nothing that needs the daemon before it
  is running, never starts it, and never prints a secret value, masked or
  not. Agent authentication accepts an `anthropic` API key (billed
  separately from any subscription), an experimental custom secret for
  `api.anthropic.com`, or a declared subscription.
- Under `sandbox` (or an invalid value), `orchestrate brief` refuses every
  harness translation that would start a local session, and `orchestrate
  plan` shows the environment and its readiness. With `local` or no line,
  both print exactly what they did before. Moving to local is the human's
  edit of the line. See `skills/orchestrate/environment.md`.
