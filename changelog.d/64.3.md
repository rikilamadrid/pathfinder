- The orchestration engine records and cleans up the Docker Sandboxes
  resources it owns (`skills/orchestrate/engine/sandbox-resources.mjs`, not yet
  wired to a command). Each run gets a run id (`YYYYMMDDTHHMMSSZ-<8 hex>`), a
  sandbox name `pf-<key>-<session>-<8 hex>`, and an atomically written owner
  record (`pathfinder.sandbox-owner/1`) under `.pathfinder/sandboxes/<key>/<runId>/`
  whose state moves only forward through prepared, created, running, stopped,
  collected or failed, and removed. Ownership is that record plus exact-name and
  workspace agreement with `sbx ls`, never a name prefix: an unrecorded `pf-`
  sandbox is never listed, stopped, or removed. Cleanup previews first, rechecks
  the record and `sbx ls` before every action, archives `owner.json`, outputs
  and logs to `.pathfinder/archives/sandboxes/<key>/<runId>/` before removing
  anything, skips running sandboxes, live or uncheckable owners, an unavailable
  or unreadable `sbx`, a recorded workspace other than exactly
  `<runDir>/workspace` or one `sbx` does not report, and unreadable records
  with a reason; nothing the sandbox writes in its workspace chooses the
  sandbox, path, or archive cleanup acts on. The project root must be an
  absolute path, and a relative one is refused. Executing a plan takes the
  root from its caller, never from the plan, and refuses a plan previewed for
  any other root. Cleanup acts only on a run directory that is exactly
  `.pathfinder/sandboxes/<key>/<runId>` under that root and is reached through
  no link, so a plan with edited run directories or keys, or a linked
  `.pathfinder` or `sandboxes` directory, is skipped. It archives only to
  `.pathfinder/archives/sandboxes/<key>/<runId>` under that root, reached
  through no link, into a new or empty directory, and never copies over an
  existing file. A linked archive path is refused, not followed, and an
  existing non-empty archive is never reused; either way the run is skipped
  before anything is removed. A directory it cannot read is reported as
  unreadable with its reason, and the other runs are still listed and
  planned. It deletes only inside the run directory without following links,
  and never runs `sbx prune`, `sbx rm --all`, or `docker`.
