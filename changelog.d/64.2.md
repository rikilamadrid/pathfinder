- The orchestration engine can prepare a bounded workspace for one sandboxed
  session and bring its results back safely
  (`skills/orchestrate/engine/sandbox-workspace.mjs`). `prepareWorkspace`
  refuses a dirty or wrong-branch claim worktree, records the dispatched head,
  and creates `.pathfinder/sandboxes/<key>/<runId>/workspace` as a standalone
  clone of the claim branch (`--no-local`, single branch, no hardlinks or
  alternates) with every remote removed, only `user.name`/`user.email` copied
  from the host, `.pathfinder-sandbox/` excluded, and inputs staged under
  `.pathfinder-sandbox/in/` at paths that cannot escape it. A workspace path
  containing `:` (ambiguous for `sbx` `PATH:TARGET`) or a line break is
  refused by name. `bundleCommand` gives the argv the sandboxed worker runs to
  produce `branch.bundle`, under `LC_ALL=C`; a session with no new commits
  produces none, reported as "no commits" only from Git's own refusal line,
  never from those words elsewhere in an error.
- `collectWorkspace` treats everything a sandbox produces as untrusted, and
  runs only once the sandbox has stopped. It reads `.pathfinder-sandbox/out/`
  without following links, rechecking that the directories it reads through
  were not replaced, refuses (never throws on) an unreadable `out/`, and
  size-limits and validates `result.json` (`pathfinder.sandbox-result/1`),
  `state.json` (only `State`, `Gate`, `Gate stage`, `Failed stage`, `Last`
  and `Next`; `State` only `adversary`, `human-gate` or `failed`, and never
  `adversary` without
  commit rights; the adversary, review and repair fields are host-owned and
  refused), and `experiments.json`/`findings.json` through the existing
  validators. It imports `branch.bundle` only for a session allowed to commit,
  only into the registered claim worktree for the key on its branch, still
  clean at the dispatched head, and only when the bundle carries exactly
  `refs/heads/<branch>`. The fetched range is inspected from the claim
  worktree before the fast-forward: merge commits, gitlinks, absolute or
  escaping symlinks, `.git` or `..` path components, changes to the exported
  `PROTECTED_PATHS` (`.gitignore`, `context/execution-mode.md`,
  `context/tracker.md`, the claim's own `context/current-ticket.md` and
  `context/handoff.md` even where the host has none yet, `.pathfinder/`,
  `.github/`, `.claude/`, `.codex/`, `.agents/`, compared as a case- and
  normalization-insensitive filesystem would check them out, so `.agentſ/` is
  `.agents/`; each is refused as itself, as anything under it, and as a file
  or link standing in for it or for one of its leading directories, so a file
  `.pathfinder` or a link `.Claude` or `context` is refused too) and more than
  `MAX_IMPORT_COMMITS` commits are refused by name. So is a tip whose paths,
  leading directories included, such a filesystem would fold onto each other
  (`A` beside `a/b/l`) when the import brings the pair; a pair the dispatched
  head already held clean, such as `Docs/` beside `docs/`, does not block an
  import that neither adds a member nor changes what one is. The import
  never replaces a file Git does
  not track in the claim worktree, such as an ignored state file, `.env` or
  `.pathfinder/` evidence: an imported path that is one, passes through one,
  or turns a directory holding one into a file is refused by name, and the
  fast-forward also runs with `--no-overwrite-ignore`. A first file added to
  an empty directory, to one holding only ignored files, or to an ignored
  directory imports when nothing stands at its own path. Symlinks are judged
  together: an imported link may climb only with leading `..`, no higher than
  its own directory, and may not lead through another symlink, so links that
  each look contained cannot compose into one that leaves the repository. A
  symlink already on the branch whose target climbs `..` after a name is the
  host's: an import is refused only when it adds, changes or removes a symlink
  on that link's way, and so could redirect it. Every refusal leaves
  the branch untouched, the temporary ref deleted, and the bundle kept for
  inspection. A bundle from a session that may not commit is refused.
  Imported commits are reported as unverified, and collect writes no state.
  The host never runs Git with the agent-written workspace as its repository
  or directory, so hostile workspace config (`core.fsmonitor`,
  `core.hooksPath`) is never executed.
- Ignore rules are host-owned at every depth: an import that adds, changes or
  deletes a `.gitignore` anywhere in the repository — `context/.gitignore`
  reading `!current-ticket.md` would un-ignore the claim's state file — is
  refused by name, in any spelling a case-insensitive filesystem or NTFS
  would check out as one. A ticket that needs an ignore-file change gets it
  from the host: the coordinator or the human commits it on the claim branch
  outside the sandbox, before or after the sandboxed session.
- An import is bounded before anything is checked out into the claim
  worktree, by limits separate from the 64 MiB compressed `branch.bundle`
  limit and the 100-commit `MAX_IMPORT_COMMITS`: the objects the commits
  bring may expand to at most `MAX_IMPORT_OBJECT_BYTES` (256 MiB), and the
  fast-forward may write at most `MAX_IMPORT_WRITTEN_PATHS` (20,000) files and
  links holding at most `MAX_IMPORT_WRITTEN_BYTES` (256 MiB), a blob counted
  once per path that uses it. A few-hundred-kilobyte bundle of a quarter
  gigabyte of zeros, or one megabyte checked out at three hundred paths, is
  refused by name with the measured size, the branch untouched and the bundle
  kept. The written limits measure what the import changes, not the whole
  tree, so a large repository is not refused for its own size. Known limits:
  fetching the bundle already inflates each object once to verify it, bounded
  by the compressed limit and the runner's timeout, and a refused import's
  objects stay unreachable in the object store until Git's garbage
  collection; every listing is read whole up to `MAX_COMMAND_OUTPUT` (16 MiB)
  and refused, never truncated, beyond it, so a repository of roughly 140,000
  tracked paths of about 70 bytes cannot import.
