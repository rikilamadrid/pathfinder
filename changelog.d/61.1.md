- Orchestration ships a second routing policy, `adaptive`, chosen with
  `<!-- pathfinder:routing-policy adaptive -->` in `context/execution-mode.md`.
  It levels each ticket from its existing estimate (2 when risk or complexity
  is `high`; 0 only for low complexity, small context and low risk; otherwise
  1, so `unassessed` risk is never 0) and selects a model tier and effort per
  session from one level × session table covering implementation, adversary,
  review and the new `repair` session, which runs one step above
  implementation. Profiles record the harness-neutral tiers `light`,
  `standard` and `strong`; translation maps them to a concrete model.
  `static` remains the default and its briefs are byte-identical.
- The Claude Code translation now honours reasoning effort: `low`, `medium`,
  `high`, `xhigh` or `max` is passed as `translation.invocation.effort`, and
  anything else is refused by name. Its tier map is
  `light=haiku standard=sonnet strong=opus`. A project may set or replace a
  harness's map with
  `<!-- pathfinder:model-tiers <harness> light=<m> standard=<m> strong=<m> -->`;
  each model must pass that harness's model check, and a malformed marker is
  refused before any brief. Codex ships no map, so a tier there is refused
  until the project sets one.
- `orchestrate brief --session repair` asks the claim's recorded policy, as
  adversary and review already did. `orchestrate plan` shows, for every
  ticket it would claim, the implementation, adversary, review and repair
  selections, and with `--harness <id>` each one's translation or its
  refusal, in text and `--json`.
